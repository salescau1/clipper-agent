[ ] ITEM 24: Preferred Languages (Trilingual) + Anti-Looping WhisperX
--------------------------------------------------------------------------------
1. Masalah & Tujuan (WHY):
   - WhisperX membawa 99+ bahasa, jadi rawan salah tebak saat mendengar bahasa daerah
     (video KDM dominan Sunda+Indo pernah disangka Spanyol/Tagalog).
   - Tujuan: sempitkan ruang tebak ke bahasa yang user pilih, dan potong looping kata
     macet + teks gaib DI SISI LOKAL supaya beban koreksi Gemini turun.
   - Gemini TIDAK dibuang (keputusan A). `correct_text_trilingual()` sudah terpasang di
     kedua jalur (stage4_subtitles.py:1231 dan :1736) dan itu yang membuat Item 21 lulus.
     Kalau dibuang, satu-satunya penjaga looping yang terbukti ikut hilang.

2. Perilaku UI di Tab Run (WHAT):
   - Lokasi: Kartu Utama Run, Baris 2, tepat di bawah baris URL.
     `Preferred Languages:  ENGLISH [ ]   INDONESIA [v]   SUNDANESE [v]`
     * ENGLISH   default OFF (dicentang untuk video review gadget/tech)
     * INDONESIA default ON
     * SUNDANESE default ON
   - Saat 'Jalankan' diklik, centang diteruskan sebagai `--lang-tags id,su`.
   - Minimal satu bahasa wajib tercentang. Kalau user mengosongkan semuanya, kembalikan
     ke `id` dan beri tanda di UI — jangan kirim `--lang-tags` kosong.

3. Logika Backend (HOW):
   File: `stages/stage4_subtitles.py`, `stages/stage4_batch.py`, `main.py`, `config.py`.

   3a. initial_prompt dinamis (SATU-SATUNYA tempat centang bahasa berpengaruh):
       * SUNDANESE aktif -> kumaha, atuh, euy, punten, naha, pisan, da, maneh, barudak,
         abah, sare, hayu, nuhun, lur, akang, teteh
       * ENGLISH aktif   -> gadget, review, worth it, podcast, creator, gaming, frame, setup
       * INDONESIA aktif -> percakapan santai umum
       Diumpankan ke `model.transcribe(..., initial_prompt=...)`.

   3b. PASANG VAD (bukan "pastikan aktif" — sekarang belum aktif sama sekali):
       Terukur 2026-09-02: kode memanggil `WhisperModel(...)` langsung
       (stage4_subtitles.py:520 dan :1696), BUKAN `whisperx.load_model` yang membawa
       Silero-VAD, dan `vad_filter` default False di faster-whisper. Jadi ini pekerjaan
       MENAMBAH, bukan menyetel.

   3c. `condition_on_previous_text = False` -> SUDAH ADA, jangan dikerjakan lagi.
       Terpasang di stage1_curate.py:233, stage4_subtitles.py:525 dan :1701.

4. JANGAN: centang bahasa TIDAK BOLEH masuk parameter `language=`
   Diukur langsung di `.whisperx-venv` (2026-09-02):
     DEFAULT_ALIGN_MODELS_TORCH 5 + DEFAULT_ALIGN_MODELS_HF 36 = 41 bahasa beralignment.
     `id` -> cahya/wav2vec2-large-xlsr-indonesian   ADA
     `en` -> WAV2VEC2_ASR_BASE_960H                 ADA
     `su` -> TIDAK ADA.  `jv` -> TIDAK ADA.
   Kalau `su` diteruskan ke `language=`, forced alignment MATI -> timestamp per kata
   hilang -> SRT 1-kata/entri hancur -> kerapatan Theme 1/3/5 kata kehilangan fondasinya.
   `language` TETAP "id". Centang bahasa hanya merakit initial_prompt (3a).

5. Target File:
   - `clipper_gui.py`            checkbox + pengiriman `--lang-tags`
   - `main.py`                   terima `--lang-tags`, teruskan ke _stage4_batch
   - `stages/stage4_batch.py`    teruskan argumen ke subprocess .whisperx-venv
   - `stages/stage4_subtitles.py` initial_prompt + VAD
   - `config.py`                 default bahasa

6. Verifikasi (WAJIB dari .whisperx-venv):
   `.whisperx-venv/Scripts/python.exe stages/stage4_batch.py --manifest <path> --lang-tags id,su`
   Cek: SRT tetap 1 kata/entri, jumlah kata ter-align > 0 dengan unaligned 0, nol looping.
   pytest di `.venv` TIDAK cukup untuk tiket ini.

[ ] ITEM 27: Kartu Run Sejajar + Rentang Jumlah Klip Min-Max + Fix Spinbox Mental
--------------------------------------------------------------------------------
1. Layout Kartu Utama Run (WHAT):
   * Baris 1: URL YouTube + tombol Paste
   * Baris 2: `Preferred Languages: ENGLISH [ ] INDONESIA [v] SUNDANESE [v]`   (Item 24)
   * Baris 3: 3 kelompok SEJAJAR HORIZONTAL dipisah pembatas vertikal:
       - Kiri   : Toggle `[Auto] [Manual]` + ikon (?) tooltip alur
       - Tengah : `Klip: [6] - [10]`
       - Kanan  : `Durasi: [60]s - [240]s`
   Tulis satuan `s` pada durasi supaya dua pasang Min-Max tidak tertukar saat dibaca.

2. Jumlah Klip jadi RENTANG PENCARIAN (keputusan C):
   Kebutuhan user: "minimal 6 klip tapi cari sampai 10". Sekarang hanya ada satu angka
   (`self.count`, gui_review.py:718, range 1-40).
   * MAX = jumlah yang DIMINTA ke Gemini. Semua yang sekarang memakai `target_count`
     memakai MAX: prompt (stage1_curate.py:341 & :350), pengambilan hasil
     (`valid_clips[:target_count]` :633), dan `max_tokens` (:484).
   * MIN = ambang PERINGATAN saja. Ganti pembanding di stage1_curate.py:636 dari MAX ke
     MIN, dan bunyikan peringatan yang menyebut angka: dapat N, minimal diminta M.
   * MIN TIDAK DIJAMIN dan jangan pernah ditulis seolah dijamin. Yield Gemini tidak bisa
     dipaksa, dan filter overlap 50% di `validate_and_normalize_clips()` masih memotong
     lagi setelahnya. Hasil kurang dari MIN -> LANJUT, jangan stop, jangan retry otomatis
     (retry membuang 1 dari 20 request/hari DAN menimpa file kurasi berisi pilihan review).
   * CLI: `--count` (= MAX) dipertahankan supaya jalur lama tidak pecah, tambah
     `--min-count`. Kirim keduanya dari GUI (clipper_gui.py:2338 dan :2346).

3. Cek kapasitas SEBELUM request dikirim:
   maks klip = durasi_video / durasi_minimal. Jadi MIN 6 klip @ 60s butuh video >= 6 menit.
   Kalau `durasi // durasi_min < MIN`, peringatkan DULU sebelum memanggil Gemini —
   lebih murah daripada user menunggu request yang mustahil berhasil.
   Teks hint kapasitas yang sudah ada (gui_review.py:790, diisi `_sync()` :838) diperbarui
   supaya memakai MIN dan MAX klip, bukan satu angka.

4. Fix angka mental — penyebabnya BUKAN QSpinBox:
   Tiket lama menuduh Qt memaksa `min <= max`. Salah. Itu kode sendiri:
   `CurationSettings._sync()` (gui_review.py:838) berisi
       `if self.max_sec.value() <= self.min_sec.value(): self.max_sec.setValue(min+10)`
   dan tersambung ke `valueChanged` (:795-796), jadi jalan di SETIAP ketikan. Mengetik
   "120" di Max: begitu digit "1" masuk, 1 <= 60 -> dipaksa jadi 70.
   Solusi (validasi visual non-blocking):
   * Buang pemaksaan nilai dari `_sync()`. Kotak bebas diketik.
   * Kalau `Max < Min` -> kotak Max merah: `border: 1px solid #e06c75; background: #2a1518;`
     dan tombol 'Jalankan' dinonaktifkan sampai valid.
   * Berlaku untuk DUA pasang: Klip Max>=Min DAN Durasi Max>=Min.

5. JANGAN biarkan dua tempat saling menimpa keadaan tombol Jalankan:
   `_set_running_ui()` (clipper_gui.py:2219) menulis `self.run_btn.setEnabled(not running)`
   TANPA SYARAT di :2226. Jadi tombol yang dinonaktifkan karena Max<Min akan HIDUP LAGI
   setiap proses selesai. Buat satu fungsi penentu tunggal (mis. `_refresh_run_enabled()`)
   yang menggabungkan "tidak sedang berjalan" AND "input valid", dan panggil itu dari
   kedua jalur. Jangan menulis `setEnabled` langsung di dua tempat.

6. Target File: `clipper_gui.py`, `gui_review.py`, `main.py`, `stages/stage1_curate.py`

7. Verifikasi tanpa membuang request Gemini: uji `_build_gemini_prompt()` dan
   `validate_and_normalize_clips()` langsung (lihat pola di
   references/curation-clip-count-and-duration.md), plus uji ketik "120" di Max dan
   pastikan angkanya tidak mental.
