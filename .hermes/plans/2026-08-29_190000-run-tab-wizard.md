# Rencana: Tab Run jadi alur bertahap (Auto / Manual)

**Tujuan:** Tab Run bisa berhenti setelah kurasi supaya user mengedit headline dan memilih
klip mana yang diunduh, lalu lanjut download → subtitle → pilih tema → render. Mode sekali
klik (Auto) tetap ada.

**Alur yang diminta user:**

    curation > edit headline/hook > pilih klip manual > download > subtitle > pilih tema > render

**Arsitektur:** state review disimpan di file kurasi yang SUDAH ADA
(`output/<creator>/<judul>/<video_id>.json`). Tidak ada format baru, tidak ada folder baru.
Karena keputusan user ditulis ke file, "lanjut besok" didapat otomatis — cukup muat file itu.

**Keputusan yang sudah dikunci user (jangan ditawar ulang):**

1. Klip yang tidak dipilih TETAP ada di file (acuan), hanya tidak diunduh.
2. Penomoran output pakai `id_klip`, jadi skip klip 3 & 4 menghasilkan file `1.`, `2.`, `5.`.
3. Preview Customize boleh memakai teks contoh (mis. "WOW!!!! INI CONTOH HEADLINE");
   teks nyata per klip datang dari file kurasi. Gaya tetap dari preset.
4. Mode Auto (sekali klik) WAJIB tetap ada, berdampingan dengan Manual.
5. File kurasi tetap satu folder dengan MP4 dan SRT. JANGAN dipindah ke folder `curation/`.
6. Pemilihan file kurasi di tab Run: daftar otomatis hasil pindai folder `output/`.

**Yang SENGAJA tidak dikerjakan sekarang** (biar tidak melebar):
- Setelan Download (buffer ekor, kualitas unduhan) — bisa nyusul kapan saja, tidak
  mempengaruhi apa pun di rencana ini.
- Headline otomatis dari Gemini saat render. Alur ini menggantikannya dengan cara yang
  lebih aman (Gemini sudah menulis di Stage 1, user mengedit sebelum render).

**Revisi keputusan (2026-08-29, setelah user membaca rencana):** kata-per-baris subtitle
DIMASUKKAN ke tab Run sebagai opsi 1 atau 3 kata (user: "kasih opsi saja biar nanti saya
setting"). Lihat Task 7b. Peringatan asimetri di Risiko #4 tetap berlaku dan harus muncul
sebagai hint di UI, bukan dihapus.

## Tahap 1 — Pondasi (belum kelihatan di UI, tapi wajib lebih dulu)

### Task 1: Buktikan `main.py stage4 --video-id` benar-benar jalan

**Objektif:** Memastikan P4 memang sudah beres, karena mode Manual memanggil stage satu per
satu dan tahap subtitle akan mati kalau ini crash.

**Files:** tidak ada perubahan kode (ini verifikasi).

Langkah:
1. Jalankan (background, WhisperX di venv terpisah jadi lambat ~2 menit/klip):

       .venv\Scripts\python.exe main.py stage4 --video-id Ad5s_0VLi7o

2. Harapan: tidak ada `AttributeError`/`TypeError`; SRT existing di-SKIP.
3. Kalau LULUS: hapus P4 dari PROGRESS.md dan dari pitfall skill `clipper-pipeline`
   (keduanya masih menyatakan ini rusak — itu informasi basi yang menyesatkan sesi berikutnya).
4. Kalau GAGAL: perbaiki dispatch `main.py stage4` supaya memanggil
   `stage4_batch.py --manifest <path>` lewat `.whisperx-venv`, karena itu jalur yang terbukti
   dipakai selama ini.

### Task 2: `only_clip` di Stage 5 harus cocokkan `clip_id`, bukan nomor urut

**Objektif:** Mencegah bug yang PASTI muncul begitu fitur skip menyala.

**Files:** Modify `stages/stage5_final.py` (di `render_manifest`, sekitar baris 639-644)

Masalah sekarang:

```python
for idx, clip in enumerate(clips, 1):
    if only_clip is not None and idx != int(only_clip):
        continue
```

`idx` = nomor urut entri di manifest. Sekarang kebetulan sama dengan `clip_id` karena semua
klip diunduh. Kalau klip 3 & 4 di-skip, manifest berisi 3 entri, jadi "Uji 1 klip" nomor 3
akan merender klip `clip_id=5`.

Perbaikan: bandingkan dengan `clip.get("clip_id")` dan jatuh ke `idx` hanya kalau field itu
tidak ada (manifest legacy).

Verifikasi:
1. Buat manifest uji dengan `clip_id` 1, 2, 5 (entri ke-3 = clip_id 5).
2. Panggil `render_manifest(..., only_clip=5)` -> harus memilih entri `clip_id=5`.
3. `only_clip=3` -> tidak ada yang dirender (klip 3 di-skip), BUKAN merender clip_id 5.
4. Manifest lama (tanpa `clip_id`) tetap berperilaku seperti sebelumnya.

### Task 3: Tambah `pilih` + `headline` ke model, lalu BUKTIKAN tulis-ulang tidak merusak Stage 2

**Objektif:** Menyediakan tempat menyimpan keputusan review, tanpa merusak manifest lama.

**Files:** Modify `models.py` (`ClipCandidate`, sekitar baris 51-61)

Tambahan:

```python
pilih: bool = Field(default=True, description="False = klip tidak diunduh (tetap jadi acuan).")
headline: str = Field(default="", description="Headline hasil edit user; kosong = pakai judul_relevan.")
```

Keduanya WAJIB punya default supaya file kurasi lama tetap tervalidasi.

**Ini bagian yang belum boleh dijanjikan tanpa dites.** `durasi_detik` adalah
`computed_field`, jadi ia ikut ter-serialize saat menulis ulang. Dan `stage2_download.py`
memvalidasi manifest lewat `CurationResult.model_validate(raw)` dengan daftar field wajib
(`url_video`, `judul_video`, `video_id`, `daftar_klip`). Pola "tulis ulang manifest lalu stage
hilir menolaknya" sudah pernah jadi masalah di proyek ini.

Verifikasi (urutan ini yang menentukan lolos/tidak):
1. Muat `Ad5s_0VLi7o.json` -> `CurationResult.model_validate`. Harus lolos TANPA field baru.
2. Set `daftar_klip[2].pilih = False`, `daftar_klip[0].headline = "UJI HEADLINE"`.
3. Tulis ke file SEMENTARA (jangan timpa file user), lalu muat lagi -> nilai bertahan.
4. `stage2_download._load_manifest(file_sementara)` harus lolos.
5. Bandingkan field selain 2 tambahan itu: harus tidak ada yang hilang atau berubah tipe.
6. Bersihkan file sementara.

## Tahap 2 — Yang langsung dirasakan user

### Task 4: Stage 2 menghormati `pilih`

**Objektif:** Klip yang tidak dicentang dilewati saat download.

**Files:** Modify `stages/stage2_download.py` (loop klip di `run()`)

Aturan: `getattr(clip, "pilih", True) is False` -> lewati, cetak alasannya
(`[3/5] SKIP: tidak dipilih user`). Klip yang tidak punya field itu = ikut diunduh
(perilaku lama).

Verifikasi: manifest dengan klip 3 & 4 `pilih=false` -> hanya 3 klip diunduh, dan nama
filenya `1. ...`, `2. ...`, `5. ...`. Jumlah entri di `manifest.json` Stage 2 = 3.

### Task 5: Headline per klip sampai ke Stage 5

**Objektif:** Tiap klip punya teks headline sendiri; preset hanya mengatur gaya.

**Files:**
- Modify `stages/stage2_download.py` — bawa `headline` (atau `judul_relevan` kalau kosong)
  ke entri manifest Stage 2, mis. field `headline`.
- Modify `stages/stage5_final.py` — di `render_manifest`, ambil `clip.get("headline")` dan
  teruskan ke `render_clip(hook=...)`.

Urutan prioritas teks headline yang jelas dan harus ditulis sebagai komentar di kode:

    headline per klip (dari manifest) > preset.headline.text > Gemini (kalau gemini_default) > skip

Alasan urutan ini: sekarang `preset.headline.text` selalu terisi ("HEADLINE1 HEADLINE2
HEADLINE3"), jadi kalau preset menang, headline per klip tidak akan pernah terpakai.

Verifikasi: render 2 klip dengan `headline` berbeda di manifest -> ekstrak frame masing-masing,
buktikan teksnya beda dan gaya (font/warna/posisi) sama. Ini WAJIB lewat pengukuran frame
nyata, bukan membaca kode.

### Task 6: Layar review kurasi

**Objektif:** UI untuk mengedit headline dan memilih klip, tersimpan ke file kurasi.

**Files:** Modify `clipper_gui.py`

Per klip tampilkan: `id_klip`, checkbox `pilih`, `judul_relevan`, kotak edit headline
(default `judul_relevan`, BUKAN `hook` — lihat Risiko), `durasi_detik`, `score`, `deskripsi`,
rentang waktu, dan **status nyata** ("MP4 ada", "SRT ada") dari keberadaan file bernomor di

Tombol: Simpan (timpa file kurasi) dan Lanjut ke Download.

Verifikasi: buka file kurasi nyata, ubah pilihan + headline, Simpan, tutup app, buka lagi,
muat file yang sama -> perubahan masih ada.

## Tahap 3 — Pembungkus

### Task 7: Toggle Auto/Manual + daftar kurasi di tab Run

**Files:** Modify `clipper_gui.py`, `main.py`

- Auto = perilaku sekarang (`main.py run --url`), satu QProcess sampai selesai.
- Manual = panggil stage satu per satu, berhenti setelah kurasi untuk review.
- Daftar kurasi: pindai `output/*/*/*.json`.

**Glob WAJIB mengecualikan `manifest.json` dan `*.subtitle.json`.** Ini jebakan yang sudah
pernah kena: pemilihan "file terbaru" mengambil manifest Stage 2 dan diam-diam memproses data
video yang salah.

Sekalian: teruskan jumlah klip. `main.py stage1` diberi opsi `--count`, dan `main.py run`
meneruskan `target_count` ke `stage1_curate.run(url, target_count)`.

Verifikasi: daftar menampilkan hanya file kurasi (bukan `manifest.json`);
`main.py stage1 --url ... --count 3` menghasilkan 3 klip (atau lebih sedikit — lihat Risiko).

### Task 7b: Opsi kata-per-baris subtitle di tab Run (1 atau 3 kata)

**Objektif:** User bisa memilih kerapatan subtitle dasar sebelum pipeline jalan.

**Files:** Modify `clipper_gui.py` (panel Subtitle di tab Run), `main.py` (opsi `--words`),
`stages/stage4_subtitles.py` (terima override), `assets/gui_settings.json` (persist pilihan)

Yang diatur adalah `settings.subtitle_target_words` (Stage 4, isi file SRT) — BUKAN
`preset.subtitle.words_per_line` (Stage 5, pemecahan saat render). Keduanya harus tetap
terpisah; jangan satukan.

Pilihan di UI: 1 kata / 3 kata (default 3).

**Hint WAJIB di UI**, jangan dihapus: memilih 1 kata mengunci SRT jadi 1 kata per entri, dan
Customize TIDAK bisa menggabungkannya kembali jadi 3 — perlu jalankan ulang Stage 4
(~2 menit/klip). Memilih 3 kata membiarkan Customize memecah lebih halus kapan saja
(`words_per_line` 1/2/3/...). Jadi 3 kata adalah pilihan yang lebih fleksibel, dan itu
sebabnya jadi default.

Verifikasi:
1. `main.py stage4 --words 1` pada satu klip -> SRT berisi 1 kata per entri (hitung dengan
   membelah blok SRT, bukan membaca kode).
2. `--words 3` -> 3 kata per entri.
3. Pilihan di GUI persist setelah app ditutup (cek `assets/gui_settings.json`).
4. Tanpa opsi -> tetap memakai `settings.subtitle_target_words` (perilaku lama).

## Risiko, tradeoff, dan hal yang harus dikatakan apa adanya ke user

1. **Jumlah klip itu permintaan, bukan jaminan.** Gemini bisa mengembalikan lebih sedikit
   kalau videonya pendek, dan `validate_and_normalize_clips()` membuang kandidat yang
   bertumpuk. Minta 8 bisa dapat 6. UI harus menyebut ini, kalau tidak user menganggapnya bug.

2. **Default headline harus `judul_relevan`, bukan `hook`.** `hook` adalah kutipan transkrip
   mentah (klip 1 = 130 karakter) yang akan dikecilkan drastis oleh auto-fit.
   `judul_relevan` sudah berbentuk headline (39 karakter). Kalau default-nya `hook`, user
   harus mengedit semua klip setiap kali — menambah kerja, bukan mengurangi.

3. **Preview headline tidak akan sama dengan output, dan itu SENGAJA.** Sudah disetujui user.
   Label di UI harus jelas menyebut itu teks contoh, kalau tidak ini terlihat seperti
   regresi dari kerja "preview == output" yang baru selesai.

4. **Kata-per-baris subtitle sengaja tidak ditaruh di Run.** Stage 5 bisa memecah lebih halus
   tapi TIDAK bisa menggabungkan kembali: SRT 3-kata bisa dipecah jadi 1-kata saat render,
   sebaliknya tidak. Jadi Stage 4 harus menulis yang kasar (3 kata) dan Customize yang
   menghaluskan. Kalau user mengunci 1 kata di Run, ia harus menjalankan ulang Stage 4
   (~2 menit/klip) untuk berubah pikiran.

5. **Dropdown tema di Run jangan menimpa `render_preset.active.json`.** Kalau menimpa,
   memilih tema di Run akan diam-diam mengubah apa yang user lihat di Customize. Teruskan
   `--preset <path>` langsung; default "Pakai yang dari Customize".

6. **Aturan pemisahan yang tidak boleh dilanggar:** Run mengatur PROSES (berapa, seberapa
   bagus, template mana), Customize mengatur TAMPILAN. Tidak ada satu setelan pun yang muncul
   di dua tempat — setelan ganda adalah akar hampir semua bug parity di proyek ini.

7. **Mode Manual mengubah arsitektur tab Run**, bukan menambah tombol. Sekarang satu QProcess
   dari awal sampai akhir; Manual perlu pemanggilan per-stage plus state "sedang di tahap mana".

8. **23 test di `tests/` sudah merah sebelum rencana ini** (konvensi folder lama), dan tidak
   ada test yang menyentuh stage5/text_engine/subtitle_engine. Jadi suite ini tidak bisa
   dipakai sebagai jaring pengaman untuk Task 2-5; verifikasi harus manual dan terukur.
   Lihat P7 di PROGRESS.md.
